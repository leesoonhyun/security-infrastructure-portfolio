# Project 01. SimmitPay 중앙 로그 수집 인프라

## 프로젝트 개요

- 형태: 4인 팀 프로젝트
- 주제: 지사·DMZ·서버 구간을 포함한 결제 서비스 인프라 설계와 중앙 로그 수집
- 개인 역할: 서버 상세 설계, DNS·중앙 로그 서버 구축, 보고서 초안 작성
- 환경: Cisco 네트워크 실습 환경, Linux, rsyslog, MariaDB, LogAnalyzer

![SimmitPay 비식별화 구성도](../assets/simmitpay-architecture.svg)

## 목표

여러 서버에서 흩어져 발생하는 시스템 로그를 한곳으로 모으고, 운영자가 웹 화면에서 검색할 수 있는 흐름을 구성하는 것이 목표였습니다.

```text
Client/Server event
  -> rsyslog 전송
  -> 중앙 로그 서버 수신
  -> MariaDB 적재
  -> LogAnalyzer 검색·확인
```

## 수행 내용

### 1. 서버 역할 분리

- DNS, Web, DB, 로그 서버의 책임을 분리했습니다.
- 네트워크 팀의 주소·구간 설계에 맞춰 서버별 연결 조건을 확인했습니다.
- 서비스 상태, 포트, 이름 해석을 순서대로 점검했습니다.

### 2. 중앙 로그 파이프라인 구성

- 각 Linux 서버가 중앙 로그 서버로 이벤트를 전달하도록 설정했습니다.
- 수신 로그를 MariaDB에 적재하고 LogAnalyzer가 조회하도록 연결했습니다.
- 시험 이벤트를 생성한 뒤 발신 호스트·서비스·시간이 화면에서 구분되는지 확인했습니다.

### 3. 통합 검증

- 단순히 화면이 열린 것을 성공으로 보지 않았습니다.
- 송신 서버의 원본 이벤트와 중앙 DB 레코드, LogAnalyzer 검색 결과를 비교했습니다.
- 네트워크 경로·서비스 상태·DB 연결·웹 조회를 구간별로 나눠 점검했습니다.

## 문제 해결 방식

로그가 화면에 보이지 않을 때 다음 순서로 범위를 줄였습니다.

1. 발신 서버에서 이벤트가 실제로 생성되는지 확인
2. rsyslog 프로세스와 전송 대상·프로토콜 확인
3. 중앙 서버 수신 포트와 방화벽 확인
4. DB 적재 여부와 테이블 상태 확인
5. LogAnalyzer DB 연결과 검색 조건 확인

이 경험을 통해 “화면이 안 뜬다”를 하나의 문제로 보지 않고, 생성-전송-수신-저장-표시의 단계로 분해하는 방법을 배웠습니다.

## 결과

- 여러 서버의 시험 로그가 중앙 DB와 LogAnalyzer에서 조회되는 흐름을 구현했습니다.
- 서버·네트워크 팀의 변경사항을 맞추기 위해 주소·포트·역할 정보를 문서로 공유했습니다.
- 완성된 팀 보고서와 별도로 본인 역할과 검증 과정을 이 문서로 재작성했습니다.

## 보안 관점의 회고

- 수집만으로는 충분하지 않으며 시간 동기화, 보관정책, 접근통제, 무결성 검증이 필요합니다.
- 운영 환경이라면 TLS 기반 전송, 최소 권한 DB 계정, 수집 실패 알림을 추가해야 합니다.
- 다음 단계로 Wazuh·IDS 이벤트까지 같은 흐름에 연결하고 싶습니다.

## 공개 범위

팀 보고서 원본과 실제 주소·계정은 공개하지 않았습니다. 구성도는 역할과 흐름만 남겨 새로 작성했습니다.
