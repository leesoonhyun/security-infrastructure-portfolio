# Project 02. Bossam Games 보안 인프라와 공격 검증

## 프로젝트 개요

- 형태: 5인 팀 프로젝트
- 주제: 게임 서비스 회사의 구간 분리, 방화벽·IDS·HIDS/SIEM 구성, 모의 공격 검증
- 개인 역할: pfSense, Wazuh, IDS 환경 구축과 결과 보고서 정리
- 팀 수행: 웹 취약점에서 서버 권한 상승까지 이어지는 공격 시나리오 재현

![Bossam Games 비식별화 방어 흐름](../assets/bossam-defense-flow.svg)

## 역할을 구분한 이유

팀은 SQL Injection, 인증 우회, 파일 업로드, 제한된 셸, 과도한 특수권한으로 이어지는 공격 경로를 검증했습니다. 저는 전체 공격을 혼자 수행했다고 표현하지 않고, **pfSense·Wazuh·IDS 구축과 팀 공격 결과의 로그·방어 관점 정리**를 개인 기여로 구분합니다.

## 목표

1. 외부·DMZ·내부·관리 구간을 분리하고 필요한 서비스만 허용하기
2. 네트워크와 호스트 이벤트를 수집해 공격 단계가 어디에 남는지 확인하기
3. 공격 성공 원인을 방화벽·WAF·권한·로그 정책의 개선안으로 연결하기

## 수행 내용

### pfSense

- 외부, DMZ, 서버, 관리 구간의 인터페이스와 정책 흐름을 정리했습니다.
- 서비스별 허용 규칙과 NAT를 구성하고 허용·차단 요청을 비교했습니다.
- 관리 접근은 별도 구간으로 제한하는 원칙을 적용했습니다.

### Wazuh

- 서버와 Agent 연결 상태를 확인하고 호스트 이벤트 수집 흐름을 구성했습니다.
- 인증·파일·권한 관련 이벤트가 대시보드에 나타나는지 시험했습니다.
- 공격 단계와 호스트 로그의 시간을 맞춰 비교했습니다.

### IDS

- Suricata와 Snort 실습 경험을 바탕으로 네트워크 경보 확인 절차를 구성했습니다.
- 시험 트래픽 후 alert 또는 `eve.json`에 이벤트가 남는지 확인했습니다.
- 탐지 결과를 ‘전부 탐지했다’고 과장하지 않고, 확인된 경보와 미확인 구간을 나눠 기록했습니다.

## 팀 공격 경로와 통제 연결

| 팀이 재현한 단계 | 확인한 위험 | 개선 방향 |
|---|---|---|
| 웹 입력점의 SQL Injection | 문자열 결합 쿼리와 입력 검증 부족 | 매개변수화 쿼리, 최소 DB 권한, WAF 보조 통제 |
| 관리자 인증 우회 | 인증 로직과 세션 검증 부족 | 서버측 인증 검증, 세션 보호, 실패 횟수 제한 |
| 위험한 파일 업로드 | 확장자·MIME·저장 경로 검증 부족 | 허용목록, 웹 루트 외부 저장, 실행권한 제거 |
| 제한된 웹 셸 | 웹 프로세스 권한과 외부 통신 | 최소 권한, egress 통제, 행위·파일 모니터링 |
| SUID 오용 권한 상승 | 불필요한 특수권한 | SUID 정기 점검, 기준선 비교, Wazuh FIM |

## 검증 방식

- 방화벽 규칙 변경 전후 접근 결과 비교
- 호스트 Agent 연결과 시험 이벤트 확인
- IDS 로그의 시간·출발지·목적지·시그니처 확인
- 공격 단계별로 ‘예방’, ‘탐지’, ‘사후 확인’ 통제를 구분

## 결과와 배운 점

- 보안 장비를 설치하는 것보다 정상·비정상 흐름을 정의하고 검증하는 일이 중요함을 배웠습니다.
- 방화벽은 허용된 웹 요청 안의 취약점까지 해결하지 못하므로 애플리케이션 보안과 계정·권한 정책이 함께 필요했습니다.
- 공격 로그를 한 장비에서만 찾지 않고 네트워크·웹·호스트 기록을 시간순으로 연결해야 했습니다.

## 한계와 다음 단계

- 모든 공격 단계를 실시간 탐지했다는 증거는 부족합니다.
- 운영 환경 수준의 고가용성·성능·오탐 튜닝은 수행하지 않았습니다.
- 다음에는 동일 공격을 반복 재현해 Wazuh·Suricata 규칙별 탐지 여부와 개선 전후 결과를 표로 남기겠습니다.

## 공개 범위

원본 보고서·워크스루·VM에는 팀원 정보, 내부 주소, 계정, 비밀번호와 실행 가능한 공격 코드가 포함될 수 있어 업로드하지 않았습니다. 이 문서는 개인 역할과 팀 결과를 구분해 다시 작성한 공개본입니다.
