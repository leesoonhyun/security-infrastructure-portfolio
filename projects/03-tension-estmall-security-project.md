# Project 03. TENsion · EstMall 침해대응 보안 프로젝트

[← 포트폴리오 홈](../README.md) · [전체 교육과정](../CURRICULUM.md) · [기술·증거](../SKILLS_EVIDENCE.md)

## 프로젝트 개요

- 기간: 2026.07.23 - 2026.08.05
- 형태: 4인 팀 종합 프로젝트
- 대상: 교육용 웹 서비스 EstMall
- 목표: 방화벽·IDS/IPS·WAF·관제를 연결하고, 허가된 시험 공격의 응답과 로그를 함께 검증
- 프로젝트 범위: Firewall·IDS/IPS·WAF·Wazuh 관제, ML 기반 이상탐지, CoreWatch-Atlas 시스템 성능 관제, FLARE-VM 기반 악성코드 분석·IOC 도출
- 개인 책임: Firewall·IDS/IPS 설계, 접근통제·탐지 규칙 적용, 재검증·문서화

![TENsion·EstMall 비식별화 방어 흐름](../assets/tension-estmall-defense-flow-public.svg)

실제 주소·계정·비밀번호·서버 경로·공격 명령은 제거한 공개용 구조입니다.

## 구축한 방어 흐름

1. 허가된 시험 요청을 격리된 교육 환경에서 발생시켰습니다.
2. nftables로 서비스별 접근 범위를 제한하고 검사 대상 트래픽을 NFQUEUE로 전달했습니다.
3. Snort 2에서 스캔·Path Traversal·SQLi·XSS·반복 로그인 징후를 탐지·차단하도록 규칙을 적용했습니다.
4. HAProxy와 ModSecurity WAF를 거쳐 Web·DB 서비스로 전달되도록 공개 진입 경로를 정리했습니다.
5. HTTP 응답과 Snort·WAF·Wazuh 로그를 시간순으로 비교했습니다.
6. 정책 변경 후 같은 시험을 반복해 차단 결과와 정상 서비스 상태를 다시 확인했습니다.

팀은 위 프로젝트 범위를 하나의 침해대응 구성으로 통합했습니다. 아래에서는 그중 제가 직접 맡거나 작성·검증에 참여한 범위를 분리해 기록합니다.

악성코드 분석은 격리된 교육 환경에서 FLARE-VM·PEStudio·Ghidra·Procmon을 사용해 정적·동적 분석 관점을 익히고, 관찰 결과를 IOC 후보와 관제 확인 항목으로 연결한 팀 프로젝트 범위입니다. 구체적인 샘플·해시·실행 정보는 제외한 [학습 노트](../labs/07-malware-analysis-basics.md)로 공개했습니다.

## 개인 기여

- nftables 기본 차단 정책과 서비스 포트 접근통제 설계
- Web 서버 직접 접근과 WAF 우회 가능성 확인, 공개 진입 경로 제한에 참여
- Snort 2와 NFQUEUE를 연결한 IDS/IPS 검사 경로 구성·검증
- 스캔·Path Traversal·SQLi·XSS·반복 로그인 징후 탐지 규칙 적용
- 동일 공격 재현 후 HTTP 응답, Snort/WAF 로그, Wazuh 경보 교차 확인
- 보안 서비스·업로드 파일·DB 백업 상태를 점검하는 셸 스크립트 작성·연동 참여
- 방화벽·IDS/IPS·자동화 결과를 개인 기여내용과 팀 최종보고서에 문서화

개인 기여 목록에 포함되지 않은 구성과 전체 서비스 통합은 팀 결과이며 개인 단독 성과로 표현하지 않습니다.

## 운영 자동화

| 점검 영역 | 공개 가능한 기능 요약 | 실행 방식 |
|---|---|---|
| 업로드 파일 | 확장자·MIME·이중 확장자·코드 패턴·SHA-256 점검 | 5분 주기 |
| SOC 상태 | nftables·NFQUEUE·Snort·Wazuh·포트·시스템 자원 확인 | 5분 주기 |
| DB 백업 검증 | 덤프·압축·해시 후 임시 DB에 실제 복원하고 테이블 확인 | 일일 실행 |
| 관제 연계 | 점검 결과를 JSON 로그로 남기고 Wazuh 커스텀 경보와 연결 | systemd timer |

자동화 항목은 팀 산출물이며, 개인 기여 문서에서 확인되는 범위에 맞춰 **작성·검증·연동 참여**로 표기했습니다.

## 공격·방어 재검증

| 시험 항목 | 확인 방법 | 결과 |
|---|---|---|
| 정상 상품 검색 | 정상 입력의 HTTP 응답과 화면 확인 | HTTP 200 |
| SQL Injection | 동일 기능에 시험 입력 후 WAF·IDS/IPS 로그 비교 | HTTP 403 |
| XSS | 요청 응답과 보안 로그의 규칙 식별자·시간 비교 | HTTP 403 |
| Path Traversal | 차단 응답과 Snort/WAF·Wazuh 증적 확인 | HTTP 403 |
| Command Injection | 차단 응답과 애플리케이션 정상 상태 재확인 | HTTP 403 |

응답 코드 하나만으로 성공을 판단하지 않고, 요청 결과 → Snort/WAF 로그 → Wazuh 경보 → 정상 서비스 확인 순서로 완료 조건을 만들었습니다.

## 문제 해결 사례

### 직접 접근과 우회 경로

보호 경로 밖에서 Web 서비스에 직접 접근할 가능성을 먼저 확인했습니다. 공개 진입점과 서비스 포트를 분리해 보고, nftables·Proxy/WAF·IPS·Web 구간을 하나씩 조정한 뒤 동일 요청으로 재검증했습니다.

### IDS/IPS 경로와 규칙

경보가 보이지 않을 때는 nftables 정책, NFQUEUE 전달, Snort 2 경보 순서로 검사 범위를 좁혔습니다. 규칙은 먼저 경보 중심으로 적용하고 정상 요청과 시험 요청을 비교한 후 차단 범위를 결정했습니다.

## 배운 점

- 보안 장비 설치보다 실제 트래픽이 의도한 보안 경로를 통과하는지 확인하는 일이 중요했습니다.
- 방화벽·IDS/IPS·WAF는 같은 문제를 중복 처리하는 장비가 아니라 서로 다른 계층을 담당합니다.
- 대시보드 집계만 보지 않고 개별 요청·응답·경보를 시간순으로 연결해야 판단 근거가 생깁니다.
- 팀 결과와 개인 기여를 분리해 기록해야 기술 역량과 협업 범위를 함께 설명할 수 있습니다.

## 별도 팀 워게임 성과

같은 3단원에서 진행한 팀 워게임은 웹 취약점 10문제를 제작·검증해 팀 3위를 기록했습니다. 이는 TENsion 최종 침해대응 프로젝트의 순위가 아닌 별도 팀 성과입니다. 자세한 공개 범위는 [워게임 환경 카탈로그](../labs/08-wargame-catalog.md)에 정리했습니다.
