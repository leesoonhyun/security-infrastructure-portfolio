# Lab 02. Security Operations & Visibility

[← 포트폴리오 홈](../README.md) · [전체 교육과정](../CURRICULUM.md) · [기술·증거](../SKILLS_EVIDENCE.md)

## 실습 범위

| 영역 | 도구 | 수행 내용 |
|---|---|---|
| 방화벽·접근통제 | pfSense, ASAv | 인터페이스·NAT·서비스별 정책 구성과 허용/차단 확인 |
| 네트워크 탐지 | Snort, Suricata | NIDS/NIPS 규칙 적용, 시험 트래픽, alert·eve 로그 확인 |
| 호스트 탐지 | OSSEC, Wazuh | Server-Agent 연결, 인증·파일·시스템 이벤트 수집 |
| 가용성 모니터링 | Zabbix, Nagios | Agent 연결과 자원·서비스 상태 확인 |
| 로그 분석 | Graylog, Splunk, LogAnalyzer | 수집·검색·필터·기초 시각화 |
| 웹 로그 | GoAccess | 접근 로그 기반 요청·상태 코드 확인 |
| 패킷 분석 | Wireshark, tcpdump | 흐름·포트·플래그와 시험 트래픽 확인 |

## 정책 검증 원칙

1. 정상 요청의 출발지·목적지·포트를 정의합니다.
2. 허용 규칙을 적용하고 실제 연결을 확인합니다.
3. 차단 조건으로 요청해 연결 결과와 방화벽 로그를 비교합니다.
4. 동일 시간대의 IDS·호스트·웹 로그를 확인합니다.
5. 정책이 넓거나 중복되지 않는지 다시 검토합니다.

## 방어 관점 회고

- IDS 경보 한 줄만으로 침해를 확정할 수 없습니다.
- 네트워크 경보, 호스트 이벤트, 인증 기록, 웹 요청을 시간순으로 연결해야 합니다.
- 탐지 규칙은 정상 트래픽 기준선과 함께 관리해야 오탐을 설명할 수 있습니다.
- 자동화 스크립트는 교육용 프로토타입과 운영 가능한 도구를 구분해야 합니다.
