# Lab 03. VulnHub CTF Learning Log

[← 포트폴리오 홈](../README.md) · [전체 교육과정](../CURRICULUM.md) · [기술·증거](../SKILLS_EVIDENCE.md)

> **Spoiler notice**: 이 문서와 연결된 풀이에는 VulnHub의 의도적으로 취약한 오프라인 VM 해결 과정이 포함됩니다. 모든 대상은 격리된 Host-only/NAT 실습망에서 실행했습니다.

## 왜 CTF를 했는가

CTF 풀이를 단순한 root 획득으로 끝내지 않고 `정찰 → 서비스 열거 → 초기 접근 → 권한 상승 → 원인 분류 → 방어책`의 흐름으로 기록했습니다. 인프라를 먼저 배운 뒤 공격자 관점으로 확인하면서, 설정 하나와 노출 정보 하나가 다음 단계로 연결되는 방식을 이해할 수 있었습니다.

`완료 - 본인 확인`은 실제 수행 기억은 있으나 현재 폴더에서 최종 flag 화면이나 단계별 기록이 모두 연결되지 않은 항목입니다. 공개 포트폴리오에서는 이 상태를 숨기지 않고, 증거를 추가할 때 `완료`로 변경합니다.

## 확인된 다섯 사례 요약

### Mercury

1. Nmap으로 서비스와 8080 웹 엔드포인트를 식별했습니다.
2. 웹 입력점에서 SQL Injection 가능성을 확인하고 DB 정보를 열거했습니다.
3. 노출된 계정 정보를 이용해 SSH 사용자 세션을 확보했습니다.
4. 인코딩된 정보를 해석해 다른 계정으로 전환했습니다.
5. `sudo -l`과 스크립트 동작을 확인해 상대경로 명령 호출에 따른 PATH hijacking을 재현했습니다.
6. user/root flag와 전체 과정을 19쪽 과제로 정리했습니다.

방어 연결: 매개변수화 쿼리, DB 최소 권한, 자격증명 분리, sudo 명령의 절대경로 사용, 실행 환경 PATH 고정.

### Ripper

1. Nmap·경로 탐색으로 웹 서비스와 노출 파일을 확인했습니다.
2. 웹 페이지와 시스템 기록에 남은 단서를 연결해 일반 사용자로 접근했습니다.
3. 시스템 파일·백업 로그의 민감정보가 관리자 접근으로 이어지는 흐름을 확인했습니다.

방어 연결: 웹 루트의 백업·로그 제거, 비밀정보 마스킹, 관리 서비스 접근망 제한, 자격증명 회전.

### Breakout

1. Nmap과 SMB 열거로 서비스·사용자를 확인했습니다.
2. 웹 소스에 남은 인코딩 데이터를 해석해 관리 화면 접근 단서를 찾았습니다.
3. 웹 관리 기능을 통해 제한된 셸과 user flag를 확인했습니다.
4. 파일 capability와 백업 정보 노출을 연결해 root flag에 도달했습니다.

방어 연결: 관리 포트 외부 차단, 소스 내 비밀 제거, 불필요한 capability 제거, 백업파일 권한·암호 관리.

### Earth

1. 인증서와 `robots.txt`를 조사해 가상 호스트와 숨은 경로를 찾았습니다.
2. 노출된 XOR 데이터를 해석해 사용자 접근 단서를 확인했습니다.
3. 웹 명령 실행 기능을 통해 제한된 셸과 user flag를 확인했습니다.
4. SUID 실행파일을 전송해 `ltrace`로 동작을 관찰하고 설정 오류를 재현했습니다.

방어 연결: 공개 메타데이터 최소화, 웹 명령 실행 제거, SUID 기준선 관리, 실행파일 무결성·행위 모니터링.

### Lupin

1. Nmap·robots·ffuf로 숨은 사용자 경로를 탐색했습니다.
2. Base58 데이터를 해석하고 보호된 SSH 키의 사용 조건을 분석했습니다.
3. 일반 사용자 접근 후 `sudo -l`과 linPEAS 결과를 검토했습니다.
4. Python 모듈 경로와 sudo/pip 정책 오용이 단계적 권한 상승으로 이어짐을 확인했습니다.

방어 연결: SSH 키 안전 보관, 모듈 디렉터리 쓰기권한 제한, sudo 허용 명령 최소화, 패키지 설치 권한 분리.
